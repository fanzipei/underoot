# Publishing 0.10.2: progress and recoverable model responses

The old dialog changed its status sentence on failure but left the heading as “generating”. Its stop button could remain visible because button display styling overrode the HTML hidden attribute. A summary-validation error therefore looked like a stalled task.

The new dialog shows five actual stages, source-chunk completion, attempted model requests, stage/total duration and successful status connections. Closing it leaves a floating task entry. Reopening queries the same user's active project task, including after a page refresh. Poll timeouts trigger reconnect messages instead of restarting AI. Server task heartbeats continue during long model/compile waits; real progress events are separate. Compilation does not imply another model request. No remaining-time estimate or fabricated overall percentage is shown.

Model summaries target 1800 characters and accept up to 3000. Invalid JSON, missing fields and longer responses feed the concrete validation error and original input back to the model. A step has at most two corrective retries, with at most three extra corrections across a job, all within the declared request budget. Authentication/configuration errors and cancellation are not retried. The original source is not clipped to conceal an error.

Validated source-chunk summaries are privately cached by user, source project, manuscript digest and model endpoint/name. Cache files contain summaries and hashes, not API keys, and use private directory/file permissions. A failed or restarted task can reuse those summaries after the author explicitly retries. In-memory task IDs themselves do not survive a server restart, which is reported distinctly.

Source transport uses at most 20000 characters, packing small subsections with their parent without crossing primary chapter/section boundaries. All headings and character ranges remain available, and concatenated chunks reproduce the source exactly. Hierarchical reduction groups by serialized input size instead of always concatenating eight summaries. Composition leaves room for validation feedback within its input budget. Request limits are conservative upper bounds, including the correction allowance.

Validation used synthetic local model servers; no paid provider requests were made. Cases cover live heartbeat during a delayed request, attempted-call counting, authorized active-job discovery, terminal failure after bounded corrections, 2500-character acceptance, correction of 3001 characters, complete-source feedback, private-cache reuse and lossless subsection packing. Browser tests verified the running view, background entry, reopening, refresh, explicit failure and a corrective response completing a real generated PDF. A private diagnostic manuscript's source blocks decreased from 126 to 66; its Slides and one-sheet Poster passed native PDF checks. These tests validate workflow and compilation, not scientific quality of arbitrary provider output.
