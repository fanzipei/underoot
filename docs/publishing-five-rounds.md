# Paper → Slides / Poster：五轮迭代记录

用于本次实现和前向验证的材料是仓库内的合成研究论文（`scripts/fixtures/publishing/`），包含研究问题、差距、方法、公式、准确率比较、图片、消融表格、实验条件和局限。数值仅用于软件测试。没有调用真实付费模型，也没有把现有用户论文送到外部服务。

| 轮次 | 检查发现 | 实际修改与复检 |
| --- | --- | --- |
| 1：检查原实现 | 摘要整段进入 `\\small` 正文，靠自动分页；图片集中附在末尾，没有内容层级；仅编译成功不能证明适合演讲或展板 | 定义有来源的论点、方法、证据、边界和可读性标准；保留原稿、全稿分块与完整笔记 |
| 2：内容提纲原型 | 初版重排已关联图注和公式，但真实编译暴露长标题页脚溢出：Slides 11 页、23 条溢出；Poster 意外占 2 页、4 条溢出 | 引入叙事角色、短要点、主张句、来源 ID、图文邻接和原始公式；将问题转入真实 PDF 检查，而不是宣布原型完成 |
| 3：可读性和几何修订 | 页脚长标题需要短显示形式；固定高度栏与 multicol 输出例程产生不希望的分页 | 保留完整标题、缩短页脚显示；海报改为独立连续栏布局，使用可读字号；修正后海报为单页，溢出清零 |
| 4：语义与版面反查 | 公式曾变成 `frac/sum` 的普通文字；转义百分号产生可见反斜杠；重复图注进入要点；按最短栏分配打乱了研究顺序 | 公式原样移植保守安全子集，数字/单位正确转义，图注单独放置；采用连续分组平衡栏位。复检示例为 9 页 Slides、1 页 Poster，无溢出；随后加入表格证据页与同名图路径歧义保护 |
| 5：前向验证与交付检查 | 不能把来源覆盖冒充科学完整性，也不能把编译成功冒充看过每页；独立安装的 skill 不能依赖应用数据库 | 检查全部 16 种模板及中文 Slides/Poster，真实编译并测量页数、文字边界和溢出；增加独立 builder/auditor、结构化提纲、完整讲稿笔记、未解决项和检查状态。保留局限主题，显示层以外的细节单独归档，不伪造主张来源 |

第五轮的逐页视觉反查还发现两处不能只靠编译审计识别的问题：`Research question` 未被识别为问题主题，曾被排到最后；已转成纯文本的百分号再次经过 LaTeX 清理时，被错误地当成注释开头，丢掉了基线和后续限定条件。已区分纯文本与 TeX 输入，并新增完整对照句和研究问题顺序的回归断言；重新生成和审查最终 PDF。

可重复验证：

```bash
npm run test:publishing
EDITORIAL_QA_OUT=<private-qa-directory> npm run test:publishing:quality
```

`test:publishing:quality` 在 XeLaTeX/Poppler 可用时生成 18 份真实 PDF，逐份检查；缺少编译器时明确报告未执行 PDF 检查。报告不会把自动边界检查记成视觉检查。代表样例会渲染为图片供人工检查；发布后的实际论文仍需作者核对科学结论与图像内容。

产品内的五步预检与这里五轮开发迭代是两回事：前者每次生成执行可记录的内容/版面处理，不额外强制五次模型调用。AI 模式负责从分块证据重写叙事，本地模式明确标为结构化草稿。数字原值不匹配、复杂表格/公式、图片歧义或真实编译失败都进入待核对项，不因模板套用完成而隐藏。
